DAF M1.2 — DEMONSTRATION AND REAL READ-ONLY GITHUB PLANNING

This is a Product-review candidate, not an AI development controller.
Imported tasks remain proposals. Nothing is executed, edited, approved or paid for.

WINDOWS (Windows 11, Intel/AMD 64-bit)
1. Save the portable ZIP supplied by the maintainer for review.
2. In File Explorer, right-click the ZIP, choose Extract All, then Extract.
3. Open the extracted DAF-win32-x64 folder and double-click DAF (DAF.exe).
Keep every file together. Do not run from inside the ZIP or copy only DAF.exe.
Electron and Python are included. No separate Python, Node, WSL, Docker, developer
tools, terminal commands or administrator installation is needed.

This candidate is unsigned. If SmartScreen or organisational policy blocks it,
stop and request an approved signed build. Do not disable or bypass protections.
Signing, clean Windows acceptance and screen-reader qualification remain gates
before public distribution. No public release has been created.

TWO DISTINCT WORKSPACES
Offline demonstration: the original assistant selection, three permission modes,
tasks, milestones and stop/recovery examples remain simulated. No network read.
Import from GitHub: real public source reads, only after your confirmation.
Future execution: unavailable. No AI providers, credentials, repository changes,
workers, automatic updates, telemetry or spending capability exists.

IMPORT A REAL PLAN
1. Choose Import from GitHub in the left sidebar.
2. Paste a GitHub JSON file link with a full 40-character commit, not a branch/tag.
   Or enter owner/repository, exact commit and file path separately.
3. Choose Review this source. Check the repository, commit and path shown.
4. Choose Allow public GitHub read, then Read plan in the native confirmation.
   Cancel is the default. DAF reads this file and its Git tree from api.github.com
   over certificate-verified HTTPS, and saves its complete source on this device.
5. Review the milestones, tasks, dependencies, acceptance criteria, permitted
   paths and hashes. Source requirements are unverified claims. The source commit
   and the plan's declared baseline may differ.
6. Close and reopen DAF. Choose Import from GitHub, then a Saved import.
   DAF revalidates the entire stored source locally; no GitHub request is made.

Only schema-1 DAF planning JSON is supported. Markdown and arbitrary repositories
without a compatible plan cannot be translated into tasks. Private repositories,
branches/tags, symlinks, submodules and unsafe paths are refused.
The maintainer walkthrough provides a genuine DAF plan and exact example link.

CANCEL AND RECOVER
Cancel import stops the owned Python process. Closing/reloading also stops it.
A complete snapshot may have been saved just before cancellation: explicitly
refresh local history before retrying. Partial staging files are never shown as
complete plans. Identical imports reuse existing bytes; conflicts never overwrite.
Network errors require an explicit retry. DAF never asks for a token.

Missing runtime / invalid response: close DAF and re-extract the complete ZIP in
a new folder. Saved planning data is separate and remains on this device.
GitHub unavailable / limited: check your connection or wait, then retry explicitly.
TLS error: check the clock and trusted network; never disable verification.
Invalid plan / rejected path: ask the maintainer to repair the source at a new
commit. DAF refuses the whole import, not just one malformed task.

Damaged snapshot / conflict: close DAF. In File Explorer enter:
%APPDATA%\DAF Offline Demo\planning-v1
Copy the identified 64-character .json file somewhere safe, then remove only
that local file if you intend to reimport. Do not edit approval fields or hashes.
Files beginning .incomplete- are interrupted staging files, not complete imports.
Preserve them for investigation or remove them while DAF is closed.
History is limited to 100 files / 32 MiB. DAF never deletes evidence automatically.
Network drives and linked/junction profile folders are unsupported.

KEYBOARD AND REMOVAL
Tab / Shift+Tab moves focus; Space / Enter activates buttons and disclosures.
Use Skip to content and View zoom. Screen-reader qualification is pending.
The X or Demo > Exit DAF closes the app. Demo progress resets; imported plans stay.
To remove DAF, close it and delete its extracted folder and downloaded ZIP.
To remove saved plans/preferences too, delete only %APPDATA%\DAF Offline Demo
after preserving any records you want. The legacy profile name is retained from
v0.2.1. No service, startup entry or background updater is installed.

LINUX
Experimental x64 package, validated on Ubuntu 24.04 with bundled Python. Requires
a graphical session, GTK 3, NSS, ALSA, system CA certificates and a working Chromium
sandbox. Extract with an archive manager and launch DAF if your desktop permits.
Do not use --no-sandbox or run as root to bypass errors. Other distributions and
consumer installation are not qualified. Data is normally under
~/.config/DAF Offline Demo/planning-v1 (XDG configuration may vary).
