# A7 controlled snapshot mutation

Product authorised two conditional, sequential, single-attempt controls: A7-C0
(sham) and A7-15 (persistent event insertion). No retry or replacement is
authorised. Gate A remains incomplete, even if both controls pass. Gate B and all
production execution capabilities remain gated. This is a diagnostic fixture,
with no Electron integration or production admission.

## Instrumentation and observation contract

The checked-in shared inspector remains byte-identical. Its canonical SHA-256 is
`53233a1165e2044858979a1c19eb13addfa454863ce834d01db586926114063d`.
`instrument_a7.py` accepts only this complete source, one unique anchor and
uniform LF/CRLF. It generates a separate header exclusively beneath `dist`, with
one synchronous boundary after snapshot 0 returns and before snapshot 1 starts.
The full inverse recovers the original bytes. The build additionally verifies
the actual compiler source/dependency paths and the complete preprocessed
header token sequence after inverse transformation. Any difference refuses the
build. No normal inspector, acquisition or acceptance policy is changed.

The fixture uses the original three-pipe inheritance list and all original
launch attributes. C0 performs no inward duplication. A7-15 makes exactly one
inward `DuplicateHandle` against the retained owned child and the existing
retained synthetic event: desired access `SYNCHRONIZE` (`0x00100000`), inheritance
`FALSE`, options `0`. There is no PID reopening, privilege change, arbitrary
process selection or handle close in the child. Neither child is resumed.

The same inspector thread executes the boundary synchronously. Independent
count calls require 3 before and 3/4 afterward. Boundary and post-inspector
outward duplicates are compared with all eight retained original objects before
bounded `NtQueryObject` observations. Event type, exact granted access and
nonsignalled state must be observed. The query buffer is 1,024 bytes; unavailable,
malformed or ambiguous results are non-passes. Retained references prevent object
destruction/reuse while comparisons run. A separate verifier reconstructs both
complete tables and the exact set difference from durable raw evidence.

C0 requires the original inspector to accept both identical three-pipe tables.
A7-15 requires the unmodified set-consistency check to emit refusal 120, with
`passed=false` and `inventoryComplete=false`. It must still have two individually
complete tables, precisely one added event, no removed/rebound pipe, repeated
event identity witnesses and complete cleanup. A fixture success marker cannot
substitute for these observations. No refusal is injected.

## Bounds and stop semantics

The existing five-second inspection deadline includes boundary and witness work.
The supervisor never enters those potentially blocking calls. It retains the
three-second Job termination wait, exit 123 and the existing 30-second parent /
35-second capture and cleanup supervision. Both snapshots retain the existing
16-handle ceiling, strict-handle policy and suspended-thread checks. The shared
384-row limit is also enforced over the combined shared/private published rows;
the private audit array is independently bounded to 128 immutable rows.

The closed common harness shape records field names, scalar types and counts
only, derived from the preserved A6 record and checked against unchanged harness
emission. It contains no host IDs or SIDs. With every integer widened to unsigned
64-bit maximum, every SID widened to 184 characters, longest Boolean spelling
and CRLF, successful C0 evidence is at most 29,141 bytes (419 rows), and A7-15 at
most 30,970 bytes (448 rows). Both fit the unchanged 32,768-byte stderr cap.
Unexpected/overflowing failure output remains a failed bounded capture, never a
partial PASS. Raw bounded captures are persisted exclusively before parsing and
separately rehashed/reparsed during readback.

Exclusive exercise/case claims prevent retries. C0 needs an independently
verified receipt, unchanged resources and confirmed cleanup before A7-15 can
start. All post-claim exceptions attempt immutable STOP publication. Storage
failure cannot guarantee successful evidence writes; an existing claim still
blocks reuse, and missing evidence is never acceptance. A failed insertion is
INCONCLUSIVE for mutation detection. An established mutation accepted or reaching
the wrong refusal is FAIL. Either ends the whole allowance, leaving later cases
NOT RUN.

## Scope retained

This tests persistent insertion instability only. It does not establish resistance
to an independently privileged external mutator, close/reopen ABA, same-count
replacement, mutation during one capture, or atomicity against concurrent hostile
host code. The trusted diagnostic host and Windows kernel remain assumptions.
The offline verifier cannot recreate a destroyed anonymous event or prove an
honest host from hashes alone. Its independent live witnesses are separate kernel
observations within that trusted host; later readback checks identities, captures,
resources and termination without launching another fixture.

Accepted M2.1A workers, binary identities, LPAC/restricting SID, ambient-write denial,
protected generated objects, low integrity, Job restrictions, parent-death cleanup,
wall supervision, closed contracts and producer/verifier separation are unchanged.
Ambient-read and periodic CPU enforcement exceptions remain confined to the fixed
accepted native operation. No plan, digest, test or receipt grants authority.

Inspection-stall/deadline failure, resumed-child qualification, wall-time
termination, Gate B, production admission, approval/grants, journalling, recovery,
publication and desktop integration require separate Product decisions. No merge,
release, tag or binary publication is authorised.
