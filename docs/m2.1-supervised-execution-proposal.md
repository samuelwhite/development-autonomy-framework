## Revised security contract

Only fixed trusted packaged native binaries may execute the approved operation.
No interpreter, shell, arbitrary command, plugin, provider, repository script or
AI-generated executable code is an admissible worker. There is no worker path
argument or source-file open: the trusted host supplies bounded original and
replacement bytes through owned IPC and alone performs filesystem operations.
No intentional ambient filesystem reads exist in the production worker.
Compiler/runtime startup uses the fixed host-derived Windows bootstrap environment;
no caller environment, credentials, arbitrary path, command line or executable is
accepted. The normal static CRT, ASLR, DEP/NX, stack checks and CFG are retained.

Each producer and verifier uses a different fresh LPAC package identity and a
different fresh restricting SID with DISABLE_MAX_PRIVILEGE | WRITE_RESTRICTED.
The child has low integrity, change-notify only, registryRead only, explicit
bounded stdio handles, no direct network or credential access, no child creation
or breakaway, and job membership established while suspended before resume.
The host independently inspects the final token, process creation identity,
image path and actual job configuration. Worker claims cannot establish them.

Profile, package root, effective TEMP, own registry storage, generated runtime,
workspace and host-private fixtures retain their sealed protections, including
OWNER RIGHTS handling. No administrator privileges, broad compatibility SID,
machine-wide ACL edits, existing system-object ACL changes or unsandboxed fallback
are permitted. Only newly owned objects can receive attempt-specific grants.
Generated profiles/storage are removed only by their recorded exact identities.

WRITE_RESTRICTED constrains writes; it does not narrow every LPAC ambient read.
The measured shared-LPAC read succeeds. **Strict per-attempt read isolation is
not established.** This risk is accepted only for this trusted deterministic
native operation. A compromised OS, administrator, broker or replaced trusted
application binary remains outside this local threat model. Build hashes establish
consistency/provenance, not publisher identity or same-user tamper resistance.

Unvalidated worker output must never enter persistent logs or diagnostic bundles.
Pipes are bounded; unexpected fields, versions, lengths, digests, diagnostics and
extra bytes refuse. Failure records contain typed constant codes, never input
text. A zero exit code or worker success statement is not verification and gives
no security, approval, execution or spending authority.

## Independent verification and preparation

The immutable canonical preparation manifest binds source plan commit/content,
baseline/blob, protected inventory, local replacement specification, policy,
attempt identity, adapter and both binary digests. Unknown fields/versions,
malformed values, noncanonical base64, invalid UTF-8, NULs and oversized inputs
fail closed. [Protocol details](../desktop/native-foundation/README.md) distinguish
host manifest validation from the narrower native request bindings.

The producer requires exactly one occurrence and performs a literal byte copy.
The separate verifier never calls or links the producer transformation. It
independently scans all possible offsets, including overlaps, recomputes source
and block hashes, compares unchanged prefix/suffix and exact replacement, and
recomputes the full candidate digest/length. Missing, extra or altered bytes
refuse. Shared hashing/strict framing code is a common-mode implementation risk;
independence is not external CI attestation or proof against every shared defect.

The trusted host checks verifier process/token/image identity and the entire
bounded response, tied to the manifest and supplied candidate. Later M2.1B must
also seal and recheck materialised artifacts before durable publication.

## Resource contract

| Limit | Contract |
| --- | --- |
| Original and candidate | 64 KiB each |
| Old and new block | 8 KiB each |
| Native wire request / response | 147,784 / 65,624 bytes maximum; verifier result exactly 88 bytes |
| Memory | 128 MiB per process |
| Processes | One per job; sequential producer/verifier; no breakaway |
| CPU | Configured two-second Job Object user-CPU limit, periodically enforced |
| Wall deadline | Independently supervised ten seconds per worker |
| Future integrated attempt / parent | 30 / 35 seconds; no automatic retries |
| Preparation | At most 16 blobs / 2 MiB; source plan at most 64 KiB |
| Future public preparation fetch | 64 bounded GitHub GETs, 192 KiB response cap, 60 seconds total |
| Future artifact/history budgets | 4 MiB per attempt; 100 preparations/attempts and 256 MiB total |

The CPU setting is defence in depth, **not a guaranteed hard two-second ceiling**.
Record actual user CPU, peak memory, wall time, exit and termination latency.
The acceptance run observed 4.859375 seconds user CPU before kernel termination.
The independent wall watchdog remains mandatory. Do not widen any limit for a
slow machine or interpret a timeout as a successful candidate.

## Preserved requirements for M2.1B

These remain mandatory and unimplemented in this slice:

- Host-owned source-specific read consent and pinned preparation, exact Git
  spelling, one existing regular Markdown file beneath docs, complete protected
  inventory and fixed deny-policy intersection. Reject Git/workflow/configuration,
  security/licence/notices, AGENTS/CLAUDE/CODEOWNERS, private/infrastructure paths,
  traversal, UNC/device/ADS/8.3 aliases, remote volumes, case collisions, links,
  reparse points, hard-link aliases and nonregular files. Retained native handles
  must establish final file/volume identities; string-prefix checks are insufficient.
- Trusted native exact-byte review, visibly escaped controls/bidi, local-change
  versus GitHub-scope provenance, Cancel by default, and independent revalidation.
  The ordinary renderer cannot substitute the reviewed bytes or approval surface.
- One-use, five-minute monotonic, volatile grants bound to OS user, manifest,
  versions/builds, source/content, proposal, baseline, workspace, attempt, stop
  epoch and limits. Reload, close, Stop, cancellation and restart revoke grants.
  Stored approval observations never reconstruct reusable bearer authority.
- Durable exclusion/admission/Stop fencing, launch intents, creation-time process
  identities, kill-on-close and parent supervision. A crash gap is outcome unknown,
  never an automatic retry. Append-only durable observations, no-overwrite artifacts,
  full-sync transactions and bounded storage cannot authenticate a same-user rewrite.
- Explicit recovery/reverification, sealed independent results and native patch
  export only. No repository apply, automatic next task, plan advancement or claim
  that local verification satisfies pending GitHub checks.

These requirements do not enable a desktop path. Existing M1.2 planning, v0.1 and
the offline demonstration keep their current boundaries. Linux execution remains
unsupported. Signing, clean nonadministrator Windows and screen-reader acceptance
are separate distribution gates.

## Stop and review gate

M2.1A is incomplete. The mandatory cancellation check failed and native testing
stopped. Later leakage, overflow, process-failure and helper/parent-death cases
were not run. The draft PR is a blocked review checkpoint, not a qualified
foundation for desktop integration. Green hosted regressions cannot override it.

The two Product exceptions do not apply to Python, arbitrary/untrusted code,
repository scripts, providers, Codex/Claude, M2.2 or M3. Future general AI execution
must separately qualify strict isolation for untrusted executable code, provider
identity, spend containment and runner trust. No broader threat model is approved.
