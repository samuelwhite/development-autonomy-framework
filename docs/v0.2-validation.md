Browser QA covers both providers without a preselected assistant; keyboard selection
and focus; automatic checking and back navigation; all three suggested tasks with
different results; all three setup failures with Retry and explicit rechecked fixes;
hidden advanced limits; edit approval and denial; failed independent checks; immediate
stop; reload during approval; retained unknown allowance; failed recovery and recovery
of the same attempt; empty custom-task refusal; escaped text; workspace navigation;
saved results and history; narrow layout; time expiry; and disabled browser storage.
State-machine tests also cover both token ceilings, time expiry while awaiting
approval, duplicate/stale decisions, every active stop/reload phase, frozen
configuration, and old/malformed stored state. Review and planning tasks do not edit,
even when the wider permission selection would allow a proposed edit.

Developer reproduction commands are in [`prototype/README.md`](../prototype/README.md)
and `CONTRIBUTING.md`. On restricted Windows environments, set TEMP/TMP/TMPDIR to an
ignored writable directory before Python tests and package smoke tests. The initial
default-temp test attempt failed during fixture setup; using that writable directory
resolved it without source changes. An isolated environment with the existing pinned
requirements was used for the 3.12 build checks.
For this UX revision, the first isolated build could not resolve PyPI within the
restricted network. Repeating the standard build and package checks with network
access succeeded; the dependency pins and runtime sources were not changed.

The [walkthrough](v0.2-ux-walkthrough.md) links updated screenshots from the tested
UI, including welcome, assistant/project selection, permissions, starter tasks,
completed progress, approval, failed setup, recovery and narrow layout.

The existing hosted PR workflow remains unchanged. Its exact-head Windows/Linux ×
Python 3.12/3.13 conclusions belong to the PR checks, not this local report. Browser
QA is local Windows Chromium evidence; it is not a Linux GUI or installer test.
Full accessibility, clean-machine packaging, real-provider auth, hard spending
limits, native isolation and real cancellation remain unverified. The five-minute
target requires observed user trials; the prototype is not evidence of live readiness.
