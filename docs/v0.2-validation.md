Browser QA covers both providers; read-only completion; edit approval and denial;
independent-check failure; immediate stop; reload during approval; retained unknown
reservation; same-attempt reconciliation; failed connection verification; empty task
refusal; escaped task text; and disabled browser storage. State-machine tests also
cover both token ceilings, time expiry while awaiting approval, duplicate/stale
decisions, every active stop/reload phase and malformed stored state.

Developer reproduction commands are in [`prototype/README.md`](../prototype/README.md)
and `CONTRIBUTING.md`. On restricted Windows environments, set TEMP/TMP/TMPDIR to an
ignored writable directory before Python tests and package smoke tests. The initial
default-temp test attempt failed during fixture setup; using that writable directory
resolved it without source changes. An isolated environment with the existing pinned
requirements was used for the 3.12 build checks.

The existing hosted PR workflow remains unchanged. Its exact-head Windows/Linux ×
Python 3.12/3.13 conclusions belong to the PR checks, not this local report. Browser
QA is local Windows Chromium evidence; it is not a Linux GUI or installer test.
Full accessibility, clean-machine packaging, real-provider auth, hard spending
limits, native isolation and real cancellation remain unverified. The five-minute
target requires observed user trials; the prototype is not evidence of live readiness.
