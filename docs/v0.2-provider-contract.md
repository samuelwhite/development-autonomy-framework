# Provider-independent integration contract (draft 1)

This is a design, not a live adapter. The reviewable TypeScript notation in
[`provider-contract.d.ts`](provider-contract.d.ts) is language-neutral at the wire
boundary; a Python implementation should validate the same closed JSON shapes.
No SDK dependency is introduced. The UI fixture implements only the simulated
journey, not this entire proposed production contract.

The renderer never owns authority or tokens. It submits intents to a local host;
the host validates identity, scope, immutable plan, reservations, expiry and stop
epoch before calling a provider adapter. Provider output is untrusted evidence.
This extends the existing ensure/lookup idea without claiming that provider start
is idempotent or that the existing experiments already form a live admission system.

## Operations and invariants

| Operation | Meaning and required behavior |
| --- | --- |
| `describe` / `probe` | Return versioned capabilities and per-check evidence. Probe does not authenticate, start a task or perform inference. Unknown capability is unsupported. |
| `beginConnection` / `cancelConnection` | Explicit connection intent; provider-controlled browser or OS secret-store handle. Never return secrets to the renderer. Login cannot start a task. |
| `connectionStatus` / `disconnect` | Read normalized readiness; revoke this connection's access without silently logging out unrelated provider sessions. |
| `start` | Only with a host-issued, validated admission handle and immutable request digest. Persist intent before launch; reject conflicts. Never automatically replay a send after ambiguous failure. |
| `events` | Ordered, deduplicated observations for an exact attempt, using durable host sequence/cursor. Missing events produce a reconciliation requirement. |
| `decide` | One request, exact proposed action digest, exact run/turn, scope, stop epoch and expiry. Only a subset of the admitted policy can be granted. Missing, stale or duplicate decisions fail closed. |
| `interrupt` | Idempotent stop intent. Return requested, confirmed, unsupported or unknown separately. No new admission after the stop fence; cancel outstanding decisions. |
| `lookup` | Resolve the original correlation key. Distinguish absent, active, terminal and unknown. Absence only permits resubmission when provider idempotency and authoritative absence are proven. |
| `resume` | Explicit new bounded segment on the exact existing session, after reconciliation and new admission. No automatic replay, “resume last”, budget reset or authority extension. |
| `close` | Bounded process shutdown and event drain. Unresolved operations retain reservations and unknown status. Never delete provider history as cleanup. |

Each request includes protocol major version and identifiers; reject unsupported
major versions, unknown enum values, malformed amounts and scope mismatches. Digest
canonical JSON, not UI text. Use integer tokens, integer micro-USD and UTC expiry
timestamps; no floating-point budget arithmetic. Every adapter advertises the exact
runtime version plus evidence for OS isolation and accounting capabilities. A
requested permission that cannot be enforced is a refusal, never a downgrade.

Events carry adapter/connection/session/turn/attempt identity, provider event ID
when available, host sequence, observation time and simulation provenance. The host
persists and deduplicates before projection. Approval events include an opaque ID,
normalized resource/operation, action digest and expiry. Do not include credentials,
full process environments or hidden reasoning. Treat path, message and diff content
as untrusted text; validate paths at the executor, and escape at the renderer.

## State and error semantics

```text
disconnected -> connecting -> ready | connection_error
ready -> admitted -> running -> awaiting_approval -> running -> verifying -> completed
                               \-> rejected / failed / limit_reached
active -> stop_requested -> stopped_confirmed | outcome_unknown
crash/disconnect -> outcome_unknown -> lookup -> stopped / failed / completed / still_active
```

`completed` at the provider layer means the provider turn ended; only DAF's independent
validator can mark a milestone accepted. Unknown terminal state, unknown token usage,
unconfirmed cancellation and provider success are separate facts. Reconciliation may
identify the old attempt as complete but cannot synthesize acceptance evidence.

Errors are structured (`unsupported_version`, `authentication_required`,
`permission_denied`, `scope_changed`, `approval_expired`, `budget_blocked`,
`rate_limited`, `provider_unavailable`, `protocol_error`, `outcome_unknown`). Include
a safe user explanation and suggested action. Retryability is advisory only; DAF's
plan limits and reconciliation rules decide whether any retry is authorized.

## Capability mapping and conformance gates

| Concern | Codex candidate | Claude candidate | Local-model extension |
| --- | --- | --- | --- |
| Transport | App server stdio; evaluate Python wrapper | Python Agent SDK | Separate inference + reviewed tool runner |
| Authentication | Managed login lifecycle / later API key | API credential-store reference | None or endpoint-specific |
| Approval | Command/file/permission requests | Permission callback and deny/ask policy | Host-controlled tool boundary |
| Identity | Thread + turn IDs | Session + host attempt correlation | Host session + request IDs |
| Stop | Turn interrupt + terminal observation | Interrupt + drained response/process observation | Transport cancellation + tool-process observation |
| Financial ceiling | Not proven for whole agent turn | SDK estimate can overshoot; not proven | No API bill is not a bound on host resources |

Before live admission, tests must cover: wrong/replayed receipts; changed configuration
or project root; stale tool approval; stop/admission races; callback failure; process
tree exit; Unicode/space/UNC/symlink paths; traversal and protected paths; dirty source
preservation; inherited hooks/MCP/settings; duplicate/out-of-order/truncated events;
crash before/after launch; cancellation timeout; absent versus unknown; reservation
retention; resumed-session accounting; missing usage; bounded retries; and independent
check failure despite a worker success message. Run exact-version conformance on
Windows and Linux. The prototype tests a subset of UI semantics only.
