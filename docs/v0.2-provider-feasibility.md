# Provider integration feasibility

Official documentation inspected on **28 October 2026**. Documentation establishes
supported interfaces, not successful integration with this app. No CLI, SDK,
provider login, account credential, model or worker was exercised for this research.
Pin versions and recheck their actual schemas at implementation time.

## Supported routes

| Provider | Proposed route | Alternatives and decision |
| --- | --- | --- |
| OpenAI Codex | Local app server over stdio | Best fit for a graphical client with authentication, approvals and streaming. Keep the transport local. |
| Claude Code | Python Agent SDK in a supervised local child process | Fits DAF's Python core and permission callbacks; supports a consistent adapter boundary. |

Codex's app server offers an initialize handshake, thread start/resume, turn start,
events, approval requests and turn interruption. Managed authentication supports
browser login, device-code login and API keys, with cancel, completion and logout
messages. Use managed login rather than the experimental externally supplied token
mode. Await terminal turn evidence after interruption; a request acknowledgement is
not result acceptance. Its raw TCP WebSocket transport is documented as experimental
and unsupported; stdio avoids exposing a listener. These are reasons to choose app
server for DAF's proposed client. [Codex app server](https://learn.chatgpt.com/docs/app-server)

Codex also documents a TypeScript SDK (Node 18+) and a stable Python SDK (Python
3.10+) that controls app server and bundles a pinned CLI runtime dependency. Evaluate
the Python wrapper against required callbacks before writing a custom protocol
client. The old `codex mcp-server` route has been removed; do not base new work on
older MCP examples. [Codex SDK](https://learn.chatgpt.com/docs/codex-sdk)

`codex exec` supplies structured events and exact-session resume for scripts. It
remains an alternative for narrow batch work, but is less convenient for this
interactive setup/approval experience. Do not use “resume last” when reconciling a
DAF job. [Non-interactive Codex](https://learn.chatgpt.com/docs/non-interactive-mode)

Claude's Agent SDK embeds the Claude Code agent in Python or TypeScript. The
CLI's `-p` mode with JSON/streaming output is a supported subprocess alternative;
plain terminal scraping and desktop automation are unnecessary. The SDK is the
better fit for interactive permission decisions. Hosted Managed Agents are a
different product and do not satisfy this local-first design.
[Agent SDK overview](https://code.claude.com/docs/en/agent-sdk/overview),
[Programmatic CLI](https://code.claude.com/docs/en/headless)

## Authentication and installation

| Area | Codex | Claude Code |
| --- | --- | --- |
| Proposed graphical connection | Provider-managed browser/device flow; API-key option later | API-account setup; no promise of Claude subscription reuse |
| Credential custody | Provider-managed storage; choose OS keyring, not copied auth files | DAF OS credential-store reference; resolve only into the isolated adapter process |
| Verify without task | Supported handshake, account metadata and capability checks; no turn start | Local binary/protocol checks first. Report API authentication unverified unless a documented non-inference check is established. Never send a hidden “hello” prompt. |
| Missing runtime | Guided versioned installation after separate user action | SDK/runtime packaging spike; no automatic remote script execution |

Codex documents ChatGPT and API-key authentication and configurable keyring,
file, automatic or ephemeral credential storage. DAF should request keyring and
fail visibly if secure persistence is unavailable; it must not inspect or copy the
user's existing credential file. [Codex authentication](https://learn.chatgpt.com/docs/auth)

Anthropic says third-party products may not offer claude.ai login or subscription
rate limits without prior approval. Therefore a DAF “Sign in with Claude” subscription
promise is not an acceptable default. The Agent SDK quickstart documents API-key
authentication and Python/TypeScript prerequisites. Provider approval or a different
documented arrangement must precede any alternative billing route.
[Agent SDK quickstart](https://code.claude.com/docs/en/agent-sdk/quickstart)

Claude Code has native Windows and Linux installation paths. Git for Windows is
recommended for Bash; current docs describe PowerShell fallback when it is absent.
Runtime availability does not imply sandbox parity.
[Claude Code setup](https://code.claude.com/docs/en/setup)

## Permission and platform limits

Codex separates sandbox permissions from approval policy. Current Windows guidance
recommends MXC on compatible devices, with legacy fallbacks and differing isolation
properties. Test effective policy and child-process behavior on the exact supported
Windows and Linux builds; do not silently weaken isolation to meet setup time.
[Codex Windows sandbox](https://learn.chatgpt.com/docs/windows/windows-sandbox)

Claude SDK permission rules and hooks can prevent a request from reaching
`canUseTool`; permissive modes can auto-allow others. DAF must configure explicit
deny/ask rules and verify callback coverage, not assume every tool call prompts.
Never enable bypass-permissions or automatic-edit modes as a simplification.
[SDK permissions](https://code.claude.com/docs/en/agent-sdk/permissions)

Claude's built-in shell sandbox supports Linux/macOS/WSL2, not native Windows.
It covers shell commands; file tools, hooks and MCP servers are outside that
sandbox. A working directory and callback are not whole-process isolation.
For initial Windows support, keep shell disabled and require a separately proven
read-only process boundary; block the live pilot if that boundary is absent.
Later shell support may require WSL2 or another reviewed OS isolation mechanism.
[Claude sandboxing](https://code.claude.com/docs/en/sandboxing)

The Python SDK exposes `interrupt()`, permission callbacks and sandbox settings.
Drain the interrupted response before starting another query. Its sandbox can fall
back to unsandboxed operation unless `failIfUnavailable` is explicitly set; disallow
unsandboxed commands as well. Its monetary limit is a client estimate that can
overshoot, not a billing guarantee. These properties are hard pilot gates.
[Python SDK reference](https://code.claude.com/docs/en/agent-sdk/python)

## Lifecycle and spending

Persist exact provider session, turn and DAF attempt identity before interpreting
events. Deduplicate observations, retain raw evidence privately with redaction,
and never interpret reconnect as permission to resubmit. After a crash, inspect
the same session and checkout; missing or ambiguous evidence means **unknown**.
Stop commits DAF's admission fence first, asks the provider to interrupt, then
observes terminal state. Terminating a local process is not proof that a remote
request stopped or billing ended. Files already changed require an explicit diff
review; cancellation is not rollback. These are DAF design requirements.

Claude documents exact-session resume and fork; a fork changes conversation history,
not filesystem isolation. Store exact IDs, never select the most recent session.
Resume must revalidate policy and carry forward DAF's lifetime reservations.
[Claude sessions](https://code.claude.com/docs/en/agent-sdk/sessions)

Claude usage totals are estimates with resume/reset and crash caveats. `maxBudgetUsd`
or `max_budget_usd` applies to the current call's own spend, while resumed totals may
include previous usage; `/clear` can reset a call budget. Subagent accounting also
differs between fields. DAF must retain its own ledger and preserve unknown exposure;
missing/zeroed crash usage is not zero cost.
[Cost and usage](https://code.claude.com/docs/en/agent-sdk/cost-tracking)

DAF's current offline ledger does not yet prove a finite maximum for an entire
provider agent turn, including hidden retries, context growth and child agents.
Disable delegation, background tasks, hooks/plugins and inherited MCP integrations
for the first pilot; sanitize provider configuration and environment. Model-service
egress and tool-network egress must be distinct permissions. A token display,
subscription usage window or client dollar estimate must never be labelled a hard
spend cap. If the admitted ceiling cannot be enforced, refuse paid launch. The
prototype's $0 statement is exact because it has no provider transport at all.
