## Implemented mechanism and lifetime

Two unnamed manual-reset events belong only to the helper. `gate` requests only
SYNCHRONIZE and is initially signalled for C0, nonsignalled for S1. `entered`
requests SYNCHRONIZE | EVENT_MODIFY_STATE and starts nonsignalled. Both have null
security attributes and non-inheritable flags. Neither enters the child handle
list. The code never obtains a modification handle for the gate and never releases
the stalled gate.

The fixed boundary follows complete snapshot 0, including PSS release, and
precedes snapshot 1. A diagnostic readiness check inspects the first inventory's
three original pipe identities; it does not move or replace `requireAccepted`.
The inspector then calls the real
`SignalObjectAndWait(entered, gate, INFINITE, FALSE)`. Only that call signals entry.
No child work, sleeps, extra process, arbitrary target or new privilege is used.

One host observer waits on `entered` using the remaining part of its original
5000-ms budget, which starts before inspection. It records its own thread ID,
actual event results and QPC observation. The supervisor never waits for that
observer to become ready. The sham inspector acknowledges observer completion
using a retained SYNCHRONIZE-only thread handle and only the remaining original
inspection budget. A missing or late acknowledgement cannot pass.

The inspector receives a strong context reference as a thread argument, including
when its scheduling is delayed beyond the deadline. Pending waits retain their
events. The observer also owns its context. The original inspector join/detach
decision is unchanged; the observer is joined only after its thread handle is
already signalled, otherwise detached. There is no `TerminateThread`, resumed
child or gate-release cleanup shortcut.

The safety-path hooks are `noexcept`, preallocated numeric/atomic operations with
static keys. They add no evidence I/O or allocation. Inspector, observer and
supervisor each have their own single-writer buffers. Publication uses
release/acquire ordering. The original deadline decision freezes the private
prefixes; later final publication counts detect observed additions beyond them.
Only frozen prefixes are emitted, after the original safety actions. No live
non-atomic `passed`, `failure` or `inventoryComplete` field is read by A8.

Retaining and detaching a thread does not prove its cleanup. Normal helper exit
must eventually terminate the still-blocked thread and release its objects.
That behaviour has **not** been exercised. The event wait deliberately holds no
application/output lock and occurs after PSS release, but it cannot establish safe
shutdown during an arbitrary in-API stall. The parent must observe helper exit;
forced outer termination is a non-pass. Microsoft documents the shutdown
deadlock risk in [ExitProcess](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-exitprocess).

## Supervisor decisions and witnesses

The generated copy retains the actual A3 supervisor, not A7's separate supervisor.
Its wait remains 5000 ms, child wait 3000 ms, and all original decision expressions,
Job termination arguments and ordering remain unchanged. `GetLastError` is
captured immediately for WAIT_FAILED, before the first new clock observation.

| Observation | C0 expectation | S1 expectation |
| --- | --- | --- |
| Actual inspector wait | WAIT_OBJECT_0 | WAIT_TIMEOUT (258) |
| Original elapsed/deadline | less than 5000 ms / false | at least 5000 ms / true |
| done / stop at cutoff | true / false | false / true |
| Inventories | two complete identical tables | complete snapshot 0 only |
| Original inspection result | true | false, original refusal retained |
| Private inspector prefix | eight rows | three rows, no call-return rows |
| Original child termination | Job exit 123, signalled, active count zero | same |
| Helper exit | normal zero | normal one, `host_failure=1` retained |

WAIT_FAILED, late WAIT_OBJECT_0, simulated timeout values, missing entry evidence,
late publication, partial output, failed Job termination, child-wait timeout or
uncertain cleanup cannot qualify S1. Snapshot-1, consistency and acceptance rows
are absent in S1; none is fabricated to reuse a successful-inspection schema.
The control outcome is separate from the original inspection outcome. Parsing
alone never sets `native_deadline_qualified`, full qualification or authority.

After the original supervisor returns by exception and before the harness closes
its original handles, A8 performs another zero-time child wait, PID/creation/exit
query, thread identity/exit query and live Job accounting query. Exit 123 and
active count zero must agree. It retains no extra Job reference. Process/thread
exit codes are checked consistently with
[TerminateProcess](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-terminateprocess).

This is a second OS observation **inside the trusted host**, not a separately
trusted live inspector. The separate readback code checks original captured bytes,
build/copy identities, exact owned fixture bytes/file IDs, generated resources and
recorded helper/child identities. It opens only those recorded PIDs, with
QUERY_LIMITED_INFORMATION | SYNCHRONIZE; a mismatched creation time, denied query,
survivor or ambiguous observation fails closed. The anonymous Job cannot be
reopened after its final handle closes.

The entered-event witness proves reaching the Windows call, not continuous kernel
suspension. Signal and wait are not guaranteed atomic. QPC supplies corroboration,
not a fabricated timer or a claim of clock accuracy. Equal/ambiguous cross-thread
ordering is rejected. No priority, affinity, timer-resolution or system-policy
change is made. See [SignalObjectAndWait](https://learn.microsoft.com/en-us/windows/win32/api/synchapi/nf-synchapi-signalobjectandwait)
and [QPC guidance](https://learn.microsoft.com/en-us/windows/win32/sysinfo/acquiring-high-resolution-time-stamps).
Observations cover their recorded cutoffs; they cannot prove every later scheduler
state before process exit. Native entry gates stay closed pending Product review.

## Remaining limitations and gates

This implementation has not demonstrated event-stall shutdown, real Windows API
hang recovery, supervisor WAIT_FAILED recovery, Job-termination failure, child-wait
timeout handling on Windows, forced outer cleanup or crash/power-loss durability.
Portable injection tests refusal and evidence handling only. No synchronous OS
call is made cancellable merely by surrounding it with a time budget.

Fresh LPAC/restricting-SID isolation, low integrity/token restrictions, strict
handle checking, mandatory ambient-write denial, explicit positive controls,
sealed identities/protected objects, three-pipe inheritance, Job/resource limits,
wall supervision, parent-death cleanup, closed contracts, producer/verifier
separation and fail-closed evidence are unchanged. The ambient-read and periodic
CPU-enforcement exceptions remain confined to the accepted fixed native operation.

No plan, test, digest, receipt or compiled binary grants authority. Gate A remains
incomplete. Gate B, resumed-child qualification, wall-time termination, production
admission/approval/grants, journalling, recovery, desktop launching and output
publication remain gated. A separate Product decision and review of native-entry
activation are required before either proposed attempt. No merge, release, tag or
binary upload is authorised or performed.
