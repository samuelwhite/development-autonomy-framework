## Test design and authority boundary

The test host wraps `CreateProcessAsUserW` in the existing maintainer harness.
Its five original startup attributes pass through unchanged, including the three
explicit stdin/stdout/stderr handles, LPAC policy, security capabilities, Job
Object and child-process restriction. The final restricted token, fresh package
and restricting SIDs, low integrity, registryRead capability, sealed generated
objects, ambient-write denial and permitted dual-grant write control are checked
by the unchanged harness.

For gate A, the host additionally creates five inheritable synthetic handles:
readable file, writable file, writable file mapping, event, and a handle to the
host process with query/duplicate rights. Host-side read/write/mapping controls
confirm the test resources are usable. None is added to the approved inheritance
list. The diagnostic child attempts the corresponding operations, including a
duplicate-handle attempt, and reports only fixed numeric observations.

Microsoft documents explicit handle-list inheritance and notes that inherited
handles retain their access rights in [process inheritance](https://learn.microsoft.com/en-us/windows/win32/procthread/inheritance).
The test must establish that unapproved inherited access is absent; successful
token composition alone cannot establish that fact. Numeric handle values in
different processes do not by themselves authenticate the underlying object.

For gate B, the candidate opens and retains each directory component and the
image without data-write or delete sharing. It rejects alternate spellings,
reparse points and existing hard links; checks normalized names, volume/file IDs,
length and SHA-256; creates the child suspended; compares OS-owned DOS/native
image paths and the mapped image name; and rechecks pinned file identity/bytes
before returning to the existing token checks and resume. Microsoft describes
the applicable [file sharing rules](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew),
[mapped-file name query](https://learn.microsoft.com/en-us/windows/win32/api/psapi/nf-psapi-getmappedfilenamew)
and [virtual memory query](https://learn.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-virtualqueryex).
These APIs are design inputs, not proof that this candidate closes every race.

The planned 20-case manifest covers hostile handles; producer/verifier controls;
substitution and modified content; existing writer/mapping capabilities; write,
rename, parent-rename and hard-link races; intentionally wrong suspended image;
post-create writes; and several alternate paths. **Only case 1 ran.** Further
reparse/junction, nonregular-file, source/workspace, concurrency and production
authority tests would still be needed even if that initial manifest completed.
