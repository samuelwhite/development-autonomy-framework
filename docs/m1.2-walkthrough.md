# M1.2 packaged planning walkthrough

The [public DAF readiness plan](https://github.com/samuelwhite/development-autonomy-framework/blob/a02b0ae561dfae11eb549d5a9c238b5c6374c0b9/docs/plans/m1.2-readiness.json)
describes actual proposed Windows and accessibility qualification work. Product
selected it for acceptance on 30 October 2026. It is not the synthetic M1.1 fixture
and does not authorise those follow-up tasks.

1. Extract the complete Windows candidate and open **DAF.exe** normally.
   No separate Python, Node, terminal, sign-in or developer setup is required.
2. Choose **Import from GitHub** in the sidebar. The page identifies itself as
   **Real read-only planning**, separate from **Offline demo · Simulated**.
3. Paste the pinned file link above. Choose **Review this source**. Verify the
   repository, exact commit `a02b0ae561dfae11eb549d5a9c238b5c6374c0b9` and
   `docs/plans/m1.2-readiness.json`. A branch/tag link refuses.
4. Choose **Allow public GitHub read…**. Inspect the native dialog; Cancel is the
   default. Choose **Read plan** to permit only these bounded public GETs.
5. Watch import progress. **Cancel import** stops the owned local process; there
   is no remote development work to cancel.
6. Inspect **DAF · m12-distribution-readiness**, scope, deliverables and provenance.
   The source commit differs from declared baseline `f0be721fb7bb4c92716c14f627b56ae79e61786b`.
7. Inspect **WINDOWS — Record clean Windows acceptance and signing status**, then
   **ACCESSIBILITY — Qualify keyboard and screen-reader planning journeys**.
   ACCESSIBILITY depends on WINDOWS; neither is completed or approved. Read the
   instructions, acceptance criteria, permitted paths and proposal hashes.
8. Close the native window. Reopen DAF, choose **Import from GitHub**, then select
   the saved plan. The complete stored source is revalidated locally, without a
   new GitHub read or native permission prompt.
9. Explicitly reimport the same link: DAF reports the existing identical snapshot,
   preserving identity and bytes. Conflicts never overwrite originals.
10. Try a branch link, traversal path or `desktop/package.json` at the pinned
    commit. Unsupported input refuses; DAF never substitutes a demo plan.
11. If GitHub is unavailable, read recovery instructions and retry only when ready.
    A damaged saved record is identified by filename, not displayed as a valid
    plan. Follow START-HERE.txt with the app closed.
12. Return to **Offline demonstration** for the unchanged simulated modes.
    Future executable work remains explicitly unavailable.

Screenshots and evidence are listed in [validation](m1.2-validation.md). CI
substitutes only the native confirmation button; transport and persistence remain
real. A separate Windows walkthrough exercises the actual native dialog.
