## Separate fixture and common detector

`fixture-host.cpp` is a separate diagnostic executable, built only by
`build-fixture.ps1`. It is not the normal candidate or an Electron asset.
Its only commands are `A4-01 probe` and `A4-02 probe`. No arbitrary handle value,
resource path, environment override, executable or script is accepted.

The original five startup attributes are retained. Only the fixture defers
installation of HANDLE_LIST until the synthetic handles exist, then installs
exactly the three original pipes plus one readable-file handle. The other four
attributes, token, LPAC, Job and bootstrap environment pass through unchanged.
The normal `gate-host.cpp` and its three-handle list are byte-identical to A3.

A4-01 includes the original, inheritable readable-file handle. A4-02 uses a
distinct inheritable DuplicateHandle alias with the same underlying kernel object
and access, and excludes the original value. Both establish parent object identity,
file identity, eligibility and the exact requested list before launch. Existing
five synthetic host controls are verified and their permitted effects restored.

The common `suspended-inspection.h` now finishes both complete PSS inventories
before interpreting the accepted-object policy. Each capture still uses only
HANDLES | THREADS, with no memory/names/clones/contexts/stacks requested. Complete
count-consistent enumeration, expected suspended thread and process identities,
all eight object comparisons per entry, strict policy flags 3 and cross-snapshot
consistency remain required. A hostile match is an explicit refusal (201), before
the existing count/pipe policy. The accepted-object policy remains exactly three
approved pipes; there is no A4 branch, extra-object exception or diagnostic allowlist
in that policy. Existing A3 validation and historical evidence remain unchanged.

After the shared detector refuses, the separate fixture supervisor requires
exactly three pipes and one read-object match in each complete inventory. In alias
mode it also requires the original numeric value absent. A second, independent
outward duplication of the intended child handle confirms CompareObjectHandles
identity and FILE_ID_INFO against the retained original. This witness runs within
the same five-second prelaunch deadline. It does not probe an absent original
numeric handle. No capability is duplicated into the child and no child handle
is closed by duplication. Failed fixture setup or a count-only refusal cannot pass.

## Supervision, evidence and independent readback

Both fixture children remain suspended. The hook is declared noreturn; it always
terminates the contained Job and enters cleanup through either an expected-refusal
control receipt or a failure. The build rejects a fixture binary importing
ResumeThread. The accepted harness bytes are preserved with exactly two diagnostic
insertions in a separate generated header.

One process, 128 MiB, periodic two-second CPU setting, independent ten-second runtime
wall protection, five-second inspection, three-second termination confirmation,
30-second helper and 35-second parent capture/cleanup bounds remain unchanged.
The runtime watchdog is retained but unreachable in these suspended-only controls;
it is not claimed to cover prelaunch work. No deadline-stall case is executed.

Separate `a4_qualify.py` invocations have exclusive, consumed case claims and no
automatic case loop. A4-02 requires a matching immutable A4-01 independent receipt,
completion/result hashes, unchanged build/source identities and a newly validated
first result. This diagnostic sequencing guard is not an execution grant.

`a4_verify.py` performs a separate readback without launching a fixture or deleting
resources. It validates the saved complete observations, exact source/binary and
historical hashes, request/result/completion consistency, original fixture file
identity and unchanged bytes, terminated/absent helper and child, and absent owned
profile, registry storage/key and synthetic credential. Receipts are exclusive
and immutable. Only bounded safe metadata and hashes are retained; no memory dump
or arbitrary child payload is published.
