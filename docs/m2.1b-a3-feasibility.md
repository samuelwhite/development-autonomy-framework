## Inspection implementation and bounds

The native entry point accepts only `case-01 probe`. The Python entry point has
an exclusive consumed A3 claim; it is an accidental-repeat guard, not admission.
The historical A1 validator/runner/schema remain unchanged, and its native command
is refused by the new native entry point. There are no deliberate-leak controls
or remaining matrix cases in this implementation.

The host creates the five original synthetic hostile objects, verifies their
actual host-side operations, restores only the explicitly permitted controls,
and retains references to these objects and the three approved IPC objects.
The original five startup attributes, token, LPAC, Job and inheritance list pass
through unchanged. No hostile numeric bindings are sent to the child.

The accepted native-foundation source is not edited. Its reviewed LF-content
SHA-256 is `deb2bf8aff650db0fdfea89939c402b507308b60bd5ed93cd5f9df9eb123a5ee`;
the retained local CRLF file hash remains
`12dc51a379a8228a1dfadd4334caeec03ae29bf10a7851966be0eaabd7e065e3`.
Build generation verifies that content, preserves its bytes, and makes exactly
two insertions: inspection immediately before ResumeThread, and a typed
successful-feasibility catch entering the existing cleanup path. The first hook
always throws after terminating/waiting for the child; it never returns to
ResumeThread. The successful catch can be reached only with complete inspection
and termination evidence. Other exceptions remain failures. Generated source,
source snapshots, compiler flags, binaries and inspections are hash-manifested.

The inspector uses only `PSS_CAPTURE_HANDLES | PSS_CAPTURE_THREADS` (132), with
context flags zero. It requests no names, memory, clones, contexts or trace data.
It retains only numeric identity/state/count/error metadata. Before each capture,
the process-handle count must be 1–16. A complete walk must end with
ERROR_NO_MORE_ITEMS, match HandlesCaptured and both independent process counts,
and contain no duplicate handle value. Exactly one primary thread must match
the retained process/thread identities, be live and suspended once, and have no
context bytes. Unsupported observations cause refusal.

Each enumerated live handle is duplicated outward, non-inheritable, with
DUPLICATE_SAME_ACCESS and never DUPLICATE_CLOSE_SOURCE. Retained copies are compared
against all eight host references. A false comparison is accepted as different
only with ERROR_NOT_SAME_OBJECT; any other error fails. Every entry must be one of
the three distinct approved pipes at its expected inherited value. Unknown,
hostile or additional objects fail. Two complete inventories and retained object
comparisons must agree; process identity is rechecked at completion. Strict-handle
policy is recorded on both rounds and must report both raising and permanent
enforcement, with no unknown flags. No policy-setting API or exception suppression
is introduced. This is not proof of the historical A1 exception's cause.

Snapshot/query/walk/duplication/comparison operations run on a dedicated trusted
host thread. A separate supervising thread waits on its thread handle for at
most 5,000 ms; completion at/after that deadline fails. It then terminates the
contained Job and waits at most 3,000 ms on the original retained process handle.
Case 01 uses termination code 123 even on feasibility success, because it never
resumes the child. Child exit, active Job count, resource use and latency are
recorded. This is controlled suspended termination, not a runtime wall-kill test.

On an inspector timeout, it is not joined indefinitely or forcibly terminated.
It retains only its own state/handles and immutable published records; the
supervisor kills/waits for the contained child and enters normal owned cleanup.
A still-blocked inspector ends with the helper process. Its timeout is always a
failure. The Python parent independently limits helper runtime to 30 seconds,
retains failure evidence, and bounds capture/cleanup work within 35 seconds.
Any unfinished cleanup is explicitly unconfirmed. Independent readback checks
terminated/absent child and helper, generated profile/storage/key/credential
absence and unchanged synthetic resources. A retained handle to a terminated
process is distinguished from a surviving process.

The existing ten-second post-resume watchdog, one-process/128 MiB Job restrictions,
periodic two-second CPU enforcement, parent-death behavior, token/LPAC, fresh
identity, low integrity, sealing and write restrictions remain unchanged. Setup
before inspection is under the outer parent bound, not the inspection timer or
runtime watchdog. Only metadata is captured by PSS; snapshot-internal allocation
is an OS API implementation detail, additionally bounded by the inspection timeout.

## Validation and limitations

Portable tests cover missing/duplicate/truncated/oversized tables, all five hostile
matches, unknown objects, pipe mismatches, API refusals, mitigation state, deadlines,
process/thread identity, incomplete observations and cleanup. They also verify
exact reversible instrumentation and refusal of other cases before Popen.
The existing four hosted Python jobs additionally run these portable tests; no
hosted step builds or executes a native diagnostic. The two desktop jobs retain
their existing audits, builds and packaged journeys, with no binary upload.

This design assumes the trusted host and OS are not compromised and that no
external privileged actor mutates the suspended process. Retaining an object does
not lock another process's handle slot. Repeated observations detect inconsistency
but are not an atomic guarantee against external ABA replacement. A result cannot
qualify sensitivity to deliberate inheritance or post-resume acquisition.

The child image contains only a fixed valid-pipe health exchange; case 01 does
not execute it. No desktop adapter, admission, approval, grant, journal, recovery,
patch publication or general execution implementation is added. Accepted workers,
contracts, policies, dependency controls, historical evidence and existing release
artifacts are unchanged.
