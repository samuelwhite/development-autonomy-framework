## Explicit activation path and release boundary

The source-controlled decision is `NATIVE_BUDGET_RELEASED = False`.
`native_entry(case, build, workers, output)` accepts only the exact names A8-C0
and A8-S1 and checks this decision before any effects, files or claim. The shared
`exercise_entry` checks it again for native mode and requires the exact fixed
`NativeExecution` adapter. No collector injection is permitted for native mode.
The command-line entry remains refusing; no CLI flag, environment setting,
dynamic import, monkeypatch, successful test or digest can release this decision.

The same entry sequence is exercised by a deliberately explicit simulated
adapter. Its mode and all records say `simulated`; global test-claim names contain
`m21b-a8-simulated`. Native adapter instances/subclasses cannot masquerade as
simulated effects. The fake collector only stages synthetic bytes and counts
calls; it uses no process API. These tests establish portable entry sequencing,
not native execution, Windows cleanup or deadline qualification.

A later Product decision would require a separately reviewed source change to
the release decision and a fresh frozen build. This preflight does not perform
that change. No private collector invocation or gate bypass is a supported
activation procedure. The source flag is a maintainer review boundary, not an
authentication mechanism against a malicious same-user Python process.

## Frozen exercise and predecessor prerequisites

Before any claim, paths must be resolved, under the owned repository `dist`,
distinct and non-overlapping. The fixed native adapter verifies all build bytes,
the complete source-file roster and every current source byte against the frozen
snapshot, actual compiler-input review, accepted workers and historical bundles.
Missing or extra frozen source files are refused. Build status/cases must still
record COMPILED_NOT_EXECUTED / NOT RUN, zero recorded build executions and no
qualification/authority. A canonical source-inventory digest is recorded
separately from the complete build-manifest digest.

Exercise v2 contains exactly: schema, mode, output, build_directory,
workers_directory, build_manifest, source_identity, cases, retries, qualified
and execution_authority. The case list is always [A8-C0, A8-S1], retries zero,
qualified false and execution_authority false. The global exclusive exercise
claim freezes this binding; every case start/result/receipt carries it.

C0 requires a fresh output and exclusive exercise/case claims. S1 requires the
same exact exercise binding and C0 global claim, matching local claim/start
records, a successful C0 result, matching original captured bytes/observations,
and the exact independently verified C0 receipt tied to that result, build and
source. An old v1 receipt, a failed receipt, a receipt copied from another exercise,
changed raw evidence or changed build/source cannot admit S1.

After the exclusive case claim, source/build verification runs again before the
collector. A change at that point consumes the claim, records STOP where storage
allows, and never invokes the collector. Existing case claims and STOP prevent
retries. A persistence failure cannot guarantee a final receipt, but exclusive
claims remain non-reusable. Independent S1 readback rechecks its predecessor;
the readback-only prerequisite option skips only the current case's duplicate
claim check, never the predecessor/STOP checks or native entry's exclusive claims.

## Receipt-field correction

Receipt schema advances from `daf-a8-independent/v1` to
`daf-a8-independent/v2`. The ambiguous `native_processes_launched` field is
replaced by `independent_readback_processes_launched`, whose required value is 0.
This means **independent readback launches zero additional processes**. It does
not assert that the diagnostic runner/host created no processes. Helper/child
execution identities remain separate evidence; they are not derived from this
readback field. Existing historical receipts are neither migrated nor relabelled.

Both the receipt writer and predecessor validation use the new exact field/schema. The
positive sequence models two distinct runner invocations with zero additional
readback launches. Negative cases reject a nonzero readback count and the old
ambiguous field. No native process-count observation was made in these tests.
