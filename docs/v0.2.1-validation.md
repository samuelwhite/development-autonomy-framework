# v0.2.1 desktop validation

Candidate based on approved main `d076ee39ee3b3561cc9457d9d2988464f6788837`.
Validation date: 29 October 2026. Product review only; no public release.

## Local evidence

- Windows x64 portable application built with Electron 45.1.0 and the committed
  npm lockfile. No application runtime dependencies are installed on first launch.
- ZIP: **158,532,517 bytes (151.2 MiB)**; extracted files: **374,111,572 bytes
  (356.8 MiB)**. SHA-256:
  `67e83779fe5de2f02ac8a7a12a810edeb242587f992d518ba0702006284c2f8f`.
  Later rebuilds can have different archive hashes/timestamps; use their sidecars.
- Built executable launches as a normal native window. Tests use a freshly
  extracted copy in a path containing spaces and Windows PATH containing only OS
  directories, so Python/Node on the host cannot be ordinary launch dependencies.
- Both approved UI suites passed in the packaged window: both assistants, automatic
  setup checks and fixes, suggested tasks, all three permission modes, edit
  approvals/denials, plan consent, three milestone reviews, exceptions, Stop,
  interruption, unknown outcomes and recovery. Screenshot assertions also cover
  narrow layouts, focus retention and no overflow.
- Packaged boundary tests verify renderer sandbox/isolation, no Node bridge,
  blocked HTTP/HTTPS/file probes and pop-ups, no local probe-server requests,
  navigation rejection, native close/relaunch and actionable renderer-crash recovery.
- Complete journey Chromium network logs are checked for zero outbound TCP/UDP
  socket events; page requests must stay on the bundled protocol. Raw logs remain
  local; only aggregate counts enter CI job summaries. A normal non-debug launch
  also exposed the expected native Windows accessibility tree and closed with Alt+F4.
- Existing Python suite: **147 passed**, local Python 3.14.4; Ruff lint/format and
  the distribution/runtime boundary check passed. The initial restricted execution
  environment could not create pytest temporary directories; rerunning with an
  explicit workspace temporary directory passed without runtime changes.
- npm audit: **0 vulnerabilities** at build time. This does not establish absence
  of future Chromium/Electron vulnerabilities; updates must be reviewed and rebuilt.

The PR's hosted results are authoritative for the exact pushed revision. Four
unchanged Python CI jobs (Ubuntu/Windows × 3.12/3.13) plus the new packaged Windows
and Ubuntu jobs must pass. Hosted run links and final outcomes will be recorded in
the PR after completion. The first desktop workflow could not start because the
repository allows only the existing pinned checkout/setup-python Actions. The
workflow now uses runner-provided Node and no artifact-upload action; repository
security settings remain unchanged.

## Remaining qualification and limitations

- **Clean consumer Windows 11 acceptance has not been performed.** This host has
  developer tools and no Windows Sandbox. Fresh extraction and PATH isolation are
  useful evidence, not a replacement for a clean-machine test. Follow the
  [acceptance procedure](v0.2.1-clean-windows.md).
- **Unsigned candidate.** SmartScreen/reputation and organisation policies may
  prevent launch. No security warning is bypassed. A signing identity, signed
  distribution and downloaded-file acceptance remain gates for public distribution.
- Windows 11 x64 is the intended first supported platform. Windows ARM64, Windows
  10, macOS and other architectures are not qualified. No MSI/MSIX/Start-menu
  installer yet; the portable ZIP meets extraction/launch/removal needs.
- Linux x64 is experimental, with Ubuntu 24.04 packaged CI validation planned.
  Its desktop libraries and sandbox policy remain OS prerequisites; no universal
  Linux installer or distribution support claim.
- Keyboard, focus, semantic roles and 200% zoom are automated checks. A full
  Narrator/NVDA review and broader assistive-technology testing remain outstanding.
- Closing clears demo progress. Reload recovery is simulated, not durable work
  recovery. No controller, real AI, authentication, project filesystem access,
  paid usage, autonomous worker, publication, merge or deployment capability exists.
- Bundled Chromium/Node costs about 357 MiB extracted. No telemetry, remote service,
  background daemon or automatic update system is installed. Maintainers must ship
  deliberately reviewed updates; this is not an unattended long-term distribution.

`src/daf`, Python package metadata, runtime controls, the v0.1 release and existing
four-job workflow are unchanged. PRs #7/#8, Victoria and private infrastructure are
outside this branch and were not modified.
