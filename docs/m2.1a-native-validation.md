## Verified cause and narrow repair

Before editing, the old harness and restricted probe reproduced the exact
producer/consumer mismatch: the complete diagnostic record was
`{"probe":"hold_ready","status":"observed","code":0}` followed by bytes
`0d 0a`. The old LF-only marker was absent. That reproduction reached wall
termination reason 1 at 10,015 ms, with 15 ms termination latency and cleanup
confirmed. Validated record bytes, raw stream hashes and the original build
identity are retained separately from the original failed run.

The diagnostic harness now requires that exact complete record with LF or CRLF
framing. Partial lines wait for completion; malformed, prefixed, suffixed and
unrelated records never establish readiness. All 140 native parser assertions
pass, including every split position across the tested stream. Producer/verifier
code, payload bytes, IPC contracts, policy, replacement bindings and approved
isolation configuration are unchanged.

The host reports readiness timing, termination reason, `TerminateJobObject`
invocation/result and retained process-handle signalling. Unexpected output stays
bounded in memory; only hashes/counts and validated scalar observations enter
persistent evidence. Rejected streams have explicitly incomplete prefix hashes,
not invented full-stream hashes. The runner saves an unconfirmed case before
launch and saves observations and cleanup before assertions. Six new portable
tests cover failure retention, missing measurements, cleanup, diagnostic handling
and the distinction between cancellation and wall expiry.
